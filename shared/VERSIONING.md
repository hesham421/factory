## 1. Authority: the filesystem

`factory.versioning.authority` — a module's versions are the folders under
`paths.modules/<MOD>/` plus git tags; no registry field, no ledger file
decides a version. The base folder is the first version; every later version
is a subfolder named by `naming.version_folder`; inside a version, one folder
per stage named by `naming.stage_folder`. The module also holds
`paths.module.state_dir` (generated), `paths.module.inputs_dir` (fetched) and
`paths.module.packages_dir` (split output):

```
<paths.modules>/<MOD>/
  <stage folders>/…                first version = the base folder itself
  <naming.version_folder>/          every later version: DELTAS ONLY (§3)
    <paths.module.change_manifest>
    <stage folders>/…
  <paths.module.state_dir>/         generated by gov.py state (§4) — the only thing engines read
  <paths.module.inputs_dir>/        inputs fetched from consumer repos (factory.inputs)
  <paths.module.packages_dir>/      split output per track (MARKER-PROTOCOL.md §7)
```

`gov.py version --new` creates the next version folder; `gov.py status`
reports versions, tags and the last committed stage per version.

## 2. Tags, branches, commits

| What | Pattern key | When |
|---|---|---|
| module version tag | `naming.tag` | at the end of the last pass of the version (`passes.<n>.then` contains `tag`); the tag freezes the version (`versioning.freeze_previous`) |
| stage commit | `naming.commit.stage` | once per stage by the orchestrator |
| gate commit | `naming.commit.gate` | once per gate, verdict in the message |
| state commit | `naming.commit.state` | when `_state/` is regenerated |
| version commit | `naming.commit.version` | when a version folder is created |

Git history is the ledger; there is no other.

## 3. Delta versions and the change manifest

`factory.versioning.delta_only` — a version > 1 contains **only what changed**:
the artifacts that were added or modified, each as a complete file, plus
`paths.module.change_manifest`. Unchanged artifacts are not re-emitted; the
previous version is frozen (its tag) and is read as baseline only. A stage in
a delta version must read the baseline of its own artifact from `_state/`
before writing the delta (contract C12).

Change manifest — written by the first stage of the delta, read by every
later stage and by the tools:

```
# CHANGE MANIFEST — CS-<MOD>-<SEQ>
Module       : <MOD>      Version: v<N>      Baseline: v<N-1>
Change type  : ADDITIVE | BREAKING
Summary      : one paragraph — what this change set does

## Per artifact
<artifact id>:
  ADDED    : <IDs created by this version — they continue the sequences>
  MODIFIED : <existing IDs whose definition changed>
  REMOVED  : <IDs retired — allowed only when Change type is BREAKING>
  UNCHANGED: <phases/blocks intentionally not re-emitted — by key/ID>
```

- **CS** is the change-set atom (`factory.ids.atoms.CS`), one per version,
  stamped in every delta artifact header and in the split manifest.
- **ADDITIVE** — nothing an existing consumer (this module, or another module
  through `XM`/`UXD`) relies on is removed or changes meaning. Processed
  without a human.
- **BREAKING** — removes, renames or changes the meaning of something a
  consumer relies on. The stage that detects it writes a BLOCKED ADR and the
  pass **stops** (`factory.ambiguity.breaking`); the change proceeds only after
  the human decision point, and every consuming module receives a resolution
  event ([XM-PROTOCOL.md §5](XM-PROTOCOL.md#5-resolution-event)).
- IDs **always continue** the previous version's sequences; a restarted
  counter is CRITICAL (C12.3).

## 4. Generated current state

`factory.versioning.current_state` — `gov.py state` folds the base version and
every delta, in version order, into one current file per artifact at
`paths.module.state_dir` named by `naming.current_state_file`, plus a merged
registry per stage and the traceability matrix. Rules:

1. engines read `_state/` **only** ([GOVERNANCE-CORE.md §4](GOVERNANCE-CORE.md#4-continuation-rule--engines-read-_state-only));
2. `gov.py analyze` fails with CRITICAL when `_state/` is older than any
   version folder it derives from (freshness);
3. `_state/` is regenerated before every stage and every gate, and committed
   (`naming.commit.state`) so a reviewer reads exactly what the engines read;
4. the analyze report and the gate record live in `_state/` too
   (`paths.module.analyze_report`, `paths.module.gate_record`).

## 5. What a consumer pins

Nothing is delivered, so there is no delivery state. The factory writes a
version into the shared repo and a consumer **pins a commit of it** — one
pointer that freezes the plan, the packages and the api-docs together, because
they are one tree.

What a delivery record used to carry now lives where it was always written:

| Fact | Where it lives | Written by |
|---|---|---|
| module, version, profile, packages, marker schema version | `paths.module.manifest_file` | the factory |
| traceability coverage | `paths.module.state_dir` (`traceability.md`) | the factory |
| analyze counts | `paths.module.analyze_report` | the factory |
| gate verdict and scores | `paths.module.gate_record` | the factory |
| execution progress (current phase, blocked, gaps) | the track's own partition (`repos.shared.partitions`) | that track |

Each has exactly one writer, so none can be overwritten by the other side.

## 6. Versioned reuse — the concept, stated once

- A committed and tagged version is **immutable**. Nothing edits it; a change
  is a new version.
- A consumer (another module through `XM`/`UXD`, or a consumer repo through
  its submodule pointer) **pins** a version explicitly. No consumer is auto-upgraded;
  a version move is an explicit change in the consumer's own next version.
- A new version of a target raises a **resolution event** for every pinned
  consumer; ADDITIVE lets the consumer stay or move, BREAKING obliges an impact
  ADR before moving.
- Cross-platform reuse (one profile's module consumed by another platform)
  follows the same three rules through the consumer repos; the factory itself
  holds one platform per repo and never imports another platform's artifacts.
