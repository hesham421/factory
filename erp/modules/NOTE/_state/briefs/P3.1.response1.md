This is a factory defect, not a module one: P3.1 cannot edit the SRS, and any module whose SRS uses `·` on that line silently loses the check. Worth a smoke-finding — either the clause tokenises on the separator set the SRS engine actually emits, or the SRS engine is pinned to a separator the clause reads.

**One judgment call worth flagging** — a line that opens with an ID and is followed by ` (` parses as an ID *definition* (`idmodel._HEAD`), so a wrapped `Orchestration`/`Repository` line beginning with `DBF-NOTE-001 (…)` truncates the enclosing API record and makes its `required-writer` / `orphans (QR)` evidence invisible. The plan therefore writes those lines unwrapped. That is a real trap for every engine that wraps prose at 90 columns, and the first draft of this plan fell into it.
